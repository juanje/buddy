## Signing in that finishes, and settings that stick

This release is about the moments where Buddy asks who you are and where it
should live. Signing in could hang forever with the browser already done;
setting up could act on a folder other than the one on screen; and the model
you picked for a provider was forgotten the moment you closed the panel. All
three are fixed, and none of them were things you did wrong.

**What you could see**

- **Signing in got stuck on "Waiting for browser" after the browser was
  already finished.** You would complete the sign-in, see the provider's own
  success page, and Buddy would sit there until it eventually gave up with a
  timeout. Behind the sign-in is a step that refreshes the list of available
  models, and it had no time limit — so when the service that serves that list
  went silent, the whole sign-in waited on it with no way out. Buddy now watches
  for the one thing that actually matters — your credential arriving — and stops
  waiting the moment it does, rather than waiting on a background step that may
  never answer.

- **A provider you had just signed into could disappear from Settings.** Add a
  provider, pick a model, use it — then reopen Settings and it was offered as
  "sign in" again, as though the last few minutes had not happened. Your
  credential was safely saved the whole time; Buddy was reading a separate
  in-memory list that the same silent service was responsible for refreshing.
  Settings now also consults what is actually on disk, so a provider you signed
  into stays signed in.

- **The model you chose for a provider was not remembered.** Pick a model for
  one provider, close Settings, reopen it, and the choice was gone — usually
  reset to the first (and priciest) option. The choice was never being written
  down. It is now kept per provider, so each one reopens on the model you last
  chose for it.

**What was one small change away from going wrong**

- **Setup could create a new assistant in the wrong folder.** On the location
  screen, once Buddy recognised a folder as an existing assistant it offered to
  import it — but typing a *different* path after that only changed what was on
  screen. Import still acted on the folder Buddy had recognised, not the one you
  were now looking at. In practice that meant importing an existing assistant
  while the box read a different, empty folder. Typing a new path now clears the
  old verdict, so the offer on screen always matches the folder in the box.
  A related timing quirk — picking a slow-to-check folder and then a quick one
  could let the slow answer land last and win — is closed by the same work.

**What changed underneath**

Three long functions that had grown well past readable each gave up one
self-contained piece, moved out with its own tests and no change to behaviour —
a first deliberate step against size that PROGRESS has tracked for a while, done
where a fix was already in the area rather than as a project of its own.

802 unit tests and 258 scenarios. If sign-in already worked for you and you had
not run into the location screen's rough edge, nothing here will look different —
these are fixes for failures that only showed up under specific timing or a
service being unreachable.
