## Pi SDK upgrade and a streaming fix

The embedded Pi SDK moves from 0.80 to 0.84, picking up compaction bug fixes, context-overflow recovery, and a handful of lock-contention improvements relevant to local models. No visible change from the upgrade itself — Buddy already coded against the delta-only streaming format the new SDK enforces.

**Windows smoke (20260809c / NFR-PORT-11):** choosing an existing empty folder as the buddy home could fail after OAuth with `EEXIST: file already exists, mkdir '…'`. Explorer marks many empty folders ReadOnly; Bun's recursive `mkdir` then throws even though Node would not. Setup now adopts empty directories (`ensureDirectory` + clear ReadOnly) instead of failing.

**What you could see**

- **After a worker crash, every word in the chat appeared twice.** Clicking "Restart" created a second listener on the same worker output stream without closing the first. Both copies forwarded every event, so the chat appended each streamed token twice — "SoySoy ** BuddyBuddy**". Restarting again made it triple. The transport is now released before reconnecting.
- **The crash itself said only "Worker exited (code 1)" with no explanation.** The worker's fatal-error message was written to stderr, but nothing subscribed to it. Stderr is now forwarded to the console.
- **On Linux, the About dialog had no icon, the Window menu was empty, and menu labels were in English regardless of the app language.** The About dialog now embeds a 64x64 icon, the empty Window submenu is hidden, and Edit/Settings/About/Window labels follow the configured language (Spanish or English).

**What was one small change away from going wrong**

- **Every Buddy conversation was written into the Pi CLI's session directory** (`~/.pi/agent/sessions/`), not the buddy instance. The SDK defaults that path when the second argument to `SessionManager.create` is omitted, and all five call sites omitted it. No one noticed because the conversations worked — but they accumulated in a directory the user never asked about, and the existing isolation guard did not cover this API. Sessions now go to `<instance>/.buddy/sessions/` with 7-day pruning, and a source guard fails when a new call omits the argument.

**What changed underneath**

The harness gained edit-failure recovery hints (the agent re-reads the file after a failed edit) and post-consolidation validation (filename checks and broken-link repair before commit). A dev setup script detects Fedora or Debian and installs system dependencies. Three regression test suites guard the Pi SDK contract: delta-only streaming, session-management API shape, and sidecar deep-import paths.

898 unit tests and 310 scenarios.
