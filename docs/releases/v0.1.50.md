## Quality fixes and learned skills

Four independent fixes that were all overdue: reflect no longer marks tasks as completed when they were merely discussed, the agent can learn new abilities that persist across sessions, portfolio areas stop triggering false work-in-progress alerts, and new users are offered an optional interview to set up their profile.

**What you could see**

- **Tasks you discussed during a session appeared as completed afterwards.** Reflect treated any task mentioned in the conversation — reorganized, moved between areas, or simply talked about — as done. A guard now requires explicit confirmation before marking a task complete: discussed is not done.
- **Work-in-progress nudges fired on areas where many projects are normal.** An area like `@work` with eight projects would trigger a daily "too many active fronts" alert, even though only one or two were actively being worked on. You can now tell Buddy an area is a portfolio area (no limit) or set a custom limit per area.

**What was one small change away from going wrong**

- **Learned skills were created but never discovered.** The consolidation cycle could create a skill file from repeated observations, but no future session knew it existed — the discovery path was severed when the AGENTS.md Skills section was removed. Skill files with `tool_name` and `tool_description` in their frontmatter are now registered as tools at session start automatically.

**What changed underneath**

The first-run greeting now offers a short optional interview — name, areas, work rhythm — so the profile starts with real context instead of blanks. User-facing documentation gained a section on learned skills ("Learns new abilities") and portfolio areas in both the capabilities page and the routing explanation.

1,448 unit tests and 576 BDD scenarios pass. Existing task lists, WIP settings, and provider configurations are unaffected.
