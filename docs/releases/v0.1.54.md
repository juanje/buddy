## PDF export on Linux

The **Export PDF** button in the file viewer now works on Linux, the same as on macOS: open a markdown document, export it, and choose where the PDF goes. The save dialog also got better on both platforms. It opens in your Downloads folder and remembers the last folder you saved to.

**What you could see**

- **Linux users can export a viewed document as a PDF.** The button used to be hidden on Linux because there was no way to produce the file there. Buddy now renders the document off screen and prints it to a PDF, keeping selectable text and avoiding page breaks in the middle of a paragraph or a code block. It works on localised desktops too: the system's "Print to File" printer is found by its translated name.
- **The save dialog opens in your Downloads folder.** It used to start wherever the app happened to be running from, which on Linux could be a folder you had never seen. It now opens in the Downloads folder your system reports, whatever it is called in your language (`Descargas`, `Downloads`, …). After you save somewhere else, the next export opens there. Cancelling changes nothing.
- **If your system has no Downloads folder configured,** the dialog opens in your home folder instead of failing silently.

**What changed underneath**

The native part of the app now has its own automated tests in CI. Before, it was only compiled when a release was built, and its tests never ran anywhere. They now run on every push, on the same Linux image the release uses, and include a check that a real PDF comes out. The release script also keeps the version in `package-lock.json` in step with the others, which the previous release missed.

1,473 unit tests, 590 BDD scenarios and 7 native tests pass. Windows still has no PDF export.
