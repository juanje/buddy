## Outside-In development tooling

Nothing changed for the person using Buddy. This release adds the development
infrastructure that will govern how every future feature is built: a
machine-tracked progress file, a CLI to advance through the development cycle,
and documentation that replaces the old prose-based tracking.

**What changed underneath**

The development process now follows a strict Outside-In cycle
(spec → BDD → TDD → green) enforced by a progress CLI rather than a
hand-edited markdown file. `specs/progress.json` tracks in-flight features
with their cycle step and scenario state; `scripts/progress.ts` validates
transitions and rejects a `done` mark when any scenario is not passing or
has no unit tests. A consistency gate (`progress-consistency.test.ts`) runs
as part of the quality gate, verifying that focus, status, and feature-file
tags agree. The old `PROGRESS.md` is now a one-line pointer to the CLI.
Separately, backward-compatibility claims about editor integration were
removed from the design docs — Buddy is its own product, not an editor
plugin, and the docs now say so.

376 BDD scenarios and 1112 unit tests pass.
