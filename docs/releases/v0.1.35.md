## Tasks replace the inbox

Buddy now manages your tasks through a dedicated `tasks()` tool instead of
asking you to edit a GTD inbox file directly. You tell Buddy what needs doing;
it writes the file, marks what's next, and warns you when you're spreading
attention too thin. Existing inboxes migrate automatically the first time you
open the app.

**What you could see**

- **A `tasks()` tool the assistant uses on your behalf.** Say "I need to call
  the dentist" and the assistant captures it as an action item — no manual
  editing. Actions have areas (`@work`, `@personal`), due dates, and next-action
  markers so the assistant knows what to surface when you ask what to focus on.
- **Every session starts with your task list available.** The assistant knows
  how many open items you have, which areas they belong to, and which one is
  marked next — without you having to ask.
- **WIP awareness built in.** When you add a task and already have five or more
  open, the assistant flags it conversationally. The limit is configurable.
- **Your existing inbox migrates automatically.** If you had a `user/inbox.md`,
  Buddy converts the action items to the new format and renames the old file.
  The first open item in each area is auto-marked as next. Nothing is lost.
- **The consolidation cycle cleans up completed tasks.** At the end of each
  daily consolidation, items you marked done and confirmed in the session log
  are removed. Items marked done but not mentioned in any log are flagged for
  your review rather than deleted silently.
- **Capture classification is now explicit.** The assistant distinguishes
  actions (captured to tasks), context (noted in the session log), reflections
  (acknowledged, written to journal at consolidation), and maturing ideas
  (parked with a revisit date). It classifies silently and only asks when the
  type is genuinely ambiguous.

**What changed underneath**

The GTD inbox structure (Capture, Next Actions, @context lists, Waiting For,
Someday/Maybe) is retired. `triage_inbox` is no longer a registered skill tool.
The `tasks()` dispatcher follows the same Domain Dispatcher Pattern as the Jira
and Slack connectors, with the same permission model: all mutations except
`remove` are allowed without confirmation, and `remove` asks first. Daily
coherence detection and the consolidation helpers were updated to read from
`user/tasks.md`; the old `detectInboxCoherence` and `findDatedInboxItems`
remain as deprecated aliases.
