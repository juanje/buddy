## Consolidation accuracy fixes

Daily consolidation no longer invents problems. Four bugs in the pre-computation layer were causing the LLM to see false data and react to it — creating phantom reminders, flagging tasks as resolved when they weren't, and ignoring the inbox migration file.

**What you could see**

- **Phantom reminders in the consolidation output.** Every task created today appeared as "due within 24h" because the created-date comment (`<!-- c:2026-09-12 -->`) was mistaken for a due date. The consolidation LLM then copied all of them to deferred.md as reminders. Now only real inline dates are matched.
- **False "task potentially resolved" flags.** Generic words like "family" or "travel" in a task matched the same word anywhere in the daily log, and a completion keyword ("completed", "updated") anywhere else in the log triggered the flag. A task about family documents and a log entry about a family visit were enough. Now tokens under 7 characters are excluded, metadata is stripped before matching, and completion language must appear on the same log line as the matched term.
- **Inbox migration skipped during consolidation.** The `inbox.md.pending-migration` file from the v0.1.40 migration safety feature was never processed because the LLM had to discover it on its own. Now the consolidation prompt header explicitly signals when the file exists, and the LLM processes it immediately.
- **Task cleanup blocked during consolidation.** The permission gate treated `tasks(remove)` as needing user confirmation — but there is no user during autonomous consolidation. Completed-task cleanup via the LLM was silently denied. Now the maintenance session allows task removal.

**What changed underneath**

The consolidation prompt header is assembled from pre-computed blocks (upcoming items, coherence flags, Hebbian data, health). Two of those blocks had bugs in their deterministic filters; a third block was missing entirely. The permission policy for unattended sessions now has three allowed kinds (identity-write, task-remove, and the default read/write within the workspace) instead of two. All four fixes follow the Outside-In cycle with BDD scenarios and unit tests.
