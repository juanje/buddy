## Post-testing bugfixes and migration safety

Six fixes from real-world testing. The most important: inbox migration no longer destroys data it can't parse.

**What you could see**

- **"Where we left off" no longer repeats on topic change.** Clicking "New topic" used to show the previous session's one-liner again. Now it clears properly and doesn't re-request.
- **Task dates match your clock, not UTC.** Night-owl users in UTC+1 no longer see yesterday's date on tasks created after midnight.
- **Workspaces directory exists in older instances.** If you created your Buddy before workspaces were added, the directory is now created at boot instead of waiting for the first write.
- **Better capture classification.** When you share something that contains obvious action items (document lists, deadlines, steps) but without directly saying "add this", Buddy now asks instead of silently filing it as context.

**What was going wrong**

- **Inbox migration destroyed tasks.** When upgrading from the old inbox.md format to tasks.md, the migration only understood checkbox items (`- [ ]`). Real inboxes had bold text, markdown links, and GTD sections — all silently dropped, then the original inbox was deleted. The migration now preserves unrecognized content as `inbox.md.pending-migration` and the next consolidation migrates it intelligently using the LLM.
- **Consolidation couldn't manage tasks.** The daily consolidation prompt told the LLM to use `tasks(list)`, `tasks(complete)`, etc., but the tool wasn't registered in maintenance sessions. Now it is.

**What changed underneath**

Safe inbox migration uses a three-phase lifecycle: boot preserves, consolidation migrates via `tasks()`, next boot cleans up. A new `hasContentBeyondStructure()` helper distinguishes truly empty inboxes from ones with unparseable content. The one-liner state uses a `oneLinerFetchedOnce` flag extracted to `src/lib/one-liner-session.ts` for testability.

1307 unit tests, 500 BDD scenarios.
