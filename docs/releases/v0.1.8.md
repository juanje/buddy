## The memory layer actually works

Six defects, all found by testing against a local model and all affecting the commercial path identically. They share a shape: **something fails and the system reports success.**

- **The Hebbian layer had never recorded a single access, on any install.** The tool-end event carries no arguments, so the path was always undefined and every read was skipped in silence. The neighbouring flags test only the tool name, so auto-commit worked perfectly and everything looked healthy. Promotion and demotion of files by use — the entire purpose of that layer — had never happened for any user.
- **A consolidation could report success having done nothing.** One that failed with a 401 finished in 22 ms, wrote "maintenance cycle completed" into the day's log, and advanced the maintenance clock over work that never happened. It could also corrupt file metadata unnoticed, because the linter ran *before* the model wrote.
- **The brain health report said 60 files were missing metadata** when they all had it and lacked one key, then listed all 60 at once. None was ever fixed. It now names the missing key and asks for eight per cycle.
- **The first-conversation interview fired on every session** of an instance in months of daily use, because the detector looked for a literal line the profile had stopped using as it grew. The injected block orders a complete rewrite of the profile — which is where earlier unexplained rewrites came from.
- **A message typed while the session was starting was discarded in silence.** It is now queued and sent once the session is ready.
- Assistant turns with no visible text no longer leave empty bubbles behind.
