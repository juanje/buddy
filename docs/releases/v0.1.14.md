## Buddy speaks your language

Deferred reminders and journal entries were written in English even when
the user's language was Spanish (or any other). These are user-facing
messages — the banner on app start, OS notifications, and the daily journal
the user reads directly — so they should match the user's language, not the
internal repo language.

**What you could see**

- **Reminders appeared in English in the banner and OS notifications.** The
  system prompt layering placed the blanket "all agent_brain/ in English"
  rule (SOUL.md) after the exception for deferred items (AGENTS.md), so the
  model followed the later, stricter instruction. The exception is now
  stated in `agents-base.md`, which redeploys on every version bump.

- **Journal entries were written in English.** The consolidation prompt ran
  autonomously with no user message to trigger language matching, and no
  explicit language instruction for the journal step. The model defaulted to
  the prompt language (English). An explicit instruction now tells it to use
  the user's language.

**What changed underneath**

The consolidation procedure's step numbering was cleaned up: the old 4/4b
split (confusing — no 4a existed) became steps 4 and 5(a/b), with a single
language instruction covering both deferred-item sources. The SOUL.md
template for new instances also gains the deferred exception so new and
existing installs are both covered.

802 unit tests and 258 scenarios. Nothing changes about how Buddy behaves
in conversation — only what language autonomous outputs (journal, reminders)
are written in.
