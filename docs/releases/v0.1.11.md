## Ask to see a file, and an app that opens

Buddy can now open a file for you. Asking to see your profile or your inbox puts
it on screen, instead of handing you a path or a link you have to notice and
click. And the app starts when you start it: a service Buddy asks about
available models had gone silent, and every launch was waiting fifteen seconds
on it before showing anything.

**What you could see**

- **"Show me my inbox" gave you a location, not the file.** Buddy has a viewer
  and had no way to open it — only you could, by finding a link and clicking.
  Now it opens the file itself, and says one useful thing about it rather than
  reciting the contents you are already looking at. Mentioning a file in passing
  still just links it; being asked to *see* one is a different request and now
  gets a different answer.

- **The window opened empty and stayed that way for twelve seconds.** Buddy
  refreshes its list of available models at startup. The host that serves that
  list began accepting connections and never answering, which is the worst way
  for a service to fail: there is no error to react to, only silence, so the
  wait ran to a fifteen-second timeout that had been inherited rather than
  chosen. Two things were wrong and both are fixed — nothing on the way to
  opening the window waits for that call any more, and the call itself now gives
  up after two seconds and carries on with the list it already had. That list is
  complete; the refresh only adds models released since.

**What was one small change away from going wrong**

- **A dependency upgrade would have quietly stopped the model list updating.**
  Buddy had been relying on a default of the library it uses to talk to model
  providers, and that default is inverted in the library's newer versions. The
  request is now stated outright, so the upgrade — still to come — cannot change
  behaviour without someone deciding it.

**What changed underneath**

The worker's startup gained its first test: it is driven with the model service
held permanently unavailable and has to finish wiring anyway. That kind of
defect is invisible to tests of the parts — every piece here was correct on its
own, and the app was unusable — so what is checked is the order they run in.
Beyond that: the file viewer's snapshot of Buddy's own prompts no longer picks
up editor leftovers left in the directory, and the check that a tool declares
which of its arguments are file paths now reads the real tool list instead of a
copy that had drifted.

777 unit tests and 256 scenarios. If Buddy was already opening quickly for you,
nothing about startup will look different — the fix removes a wait that only
appears when that service is unreachable.
