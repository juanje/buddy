## Show files and export PDFs from the viewer

Two buttons in the file viewer footer. **Show in Folder** opens the native file
manager with the document selected — only for files in `user/` and `downloads/`,
never for internal brain files. **Export PDF** renders the viewed markdown to a
multi-page A4 document and lets you save it wherever you choose.

**What you could see**

- **A new "Show in Folder" button when viewing user documents.** Opens Finder
  (macOS) or Nautilus (Linux) with the file highlighted, so you can move, rename
  or share it without hunting through directories.

- **A new "Export PDF" button on viewed markdown files (macOS only).** Generates
  a clean, light-themed PDF with proper A4 pages. Page breaks avoid splitting
  headings, paragraphs, tables and code blocks. The button does not appear on
  Linux, where the underlying API is not available.

**What changed underneath**

The PDF pipeline went through three iterations in one session. `window.print()`
produces a blank dialog on WKWebView; `printOperationWithPrintInfo` deadlocks
the main thread. The shipped path creates an offscreen WKWebView, measures the
document height, tiles it into A4-sized slices whose boundaries snap to block
elements, captures each slice with `createPDF`, and merges them with PDFKit.
The Tauri capability set was extended for `reveal-item-in-dir` and filesystem
writes to support both features.

1381 unit tests, 6 Rust pagination tests, tsc and vite build green.
