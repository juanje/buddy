## OpenAI API key actually works

Adding OpenAI via API key appeared to succeed — the provider showed up in Settings, its models listed correctly — but selecting it always reverted silently to the previous provider. The root cause was invisible from the outside: OpenAI has two providers inside the SDK, one for OAuth (ChatGPT Plus/Pro subscriptions) and one for direct API keys (api.openai.com). Buddy routed every OpenAI operation to the OAuth-only provider, so an API key registered there was ignored by the auth check that runs before every model switch.

**What you could see**

- **Switching to OpenAI after adding it via API key did nothing.** The provider appeared in Settings and its models listed, but clicking one always snapped back to the previous provider with no error message. The API key was valid and correctly stored — the problem was that it was stored under a provider that only accepts OAuth, so the SDK rejected it silently.
- **When a model switch failed for any reason, nothing told you.** The catch block reverted to the previous provider without surfacing the error. A new error message now appears below the model selector when a switch fails.

**What changed underneath**

The provider mapping layer now takes the authentication type into account: API key operations route to the SDK provider that supports API keys, and OAuth operations route to the one that supports OAuth. The auth status scanner checks both and deduplicates them into a single entry. Tests that computed dates against the real clock now mock system time, fixing a midnight-boundary flake in the task age assertions.

1 426 tests green. Existing OAuth logins and all other providers are unaffected.
