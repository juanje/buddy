## Docs stay current after upgrades

Updating Buddy could leave the built-in documentation pages a version behind, even though the app itself had moved on. After a failed or interrupted first launch, the next start treated the update as already applied and never copied the new pages. Daily review could also try to "fix" navigation files that were never meant to have metadata, and insert it in the wrong place.

**What you could see**

- **The help pages still described an older Buddy after you installed a new version.** Features added in that release — portfolio areas, learned skills — were missing from `~/.buddy/docs/` even though the app already had them. Documentation now copies on every launch, after the window is already up, so a crash during the previous update no longer leaves those pages stuck.
- **Daily review appended metadata to the bottom of index files.** Navigation hubs like `agent_brain/projects/index.md` were flagged as missing frontmatter. The review then tried to add it and often wrote it at the end of the file instead of the top. Those files are now left alone.

**What was one small change away from going wrong**

- **Dev scripts that talk to OpenAI via API key still used the OAuth-only provider.** The v0.1.49 Settings fix did not reach `test-reflect`, `test-consolidation`, or `eval-markov`. Nobody hitting those scripts from a key-only setup would have gotten a working model. They now pass the same authentication type as the app.

**What changed underneath**

Brain-health repair now lists missing skill-tool fields (`tool_name`, `tool_description`) before generic metadata, so a learned skill that is missing both is not "fixed" as if it were an ordinary page.

1,451 unit tests and 578 BDD scenarios pass. Existing instances, prompts, and provider settings are unchanged.
