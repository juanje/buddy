## Pi SDK 1.0 and test reliability on Linux

Buddy now runs on Pi SDK 1.0.1, picking up upstream bug fixes for session forks, prompt submission speed on long sessions, and tool containment. Three security vulnerabilities in test tooling (vitest, devalue) are also resolved.

**What you could see**

- **Tests failed on a Spanish-locale Linux system even though nothing was wrong.** Node 21+ exposes the OS locale through `navigator.language`, and several BDD scenarios assumed English without setting it. A global hook now pins the test locale to English; scenarios that test a specific language override it explicitly.
- **The worker-startup test timed out intermittently under CPU pressure.** The dynamic import of the full Pi SDK graph takes ~3.6 s alone, and the default 5 s vitest timeout left no margin when other tests ran in parallel.

**What was one small change away from going wrong**

- **A future Pi SDK update could silently break deep imports.** Pi AI moved from a nested dependency to a hoisted one in 1.0, changing every internal file path Buddy reaches. The existing `catch(() => {})` blocks would have swallowed the error. Contract tests now verify that every deep import resolves on disk, so a moved file fails a test instead of failing at runtime.

**What changed underneath**

Pi SDK updated from 0.84 to 1.0.1. vitest updated from 3 to 5 (security fix, no test changes needed). The progress CLI gained a `sync` command that auto-discovers BDD scenarios from `.feature` files, and `advance` now requires at least one registered scenario before leaving `bdd_red` — closing a gap where a feature could reach `done` validation with an empty scenario list.

1,457 unit tests and 581 BDD scenarios pass. The OpenAI Codex OAuth race workaround remains necessary in 1.0.1.
