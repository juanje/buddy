## Files Buddy mentions are files you can open

When Buddy told you where something lived, it gave you a path — accurate,
and useless unless you knew your way around a directory tree. Now the files it
names are links: click one and it opens inside Buddy, in the same panel that
already handled links written by hand. Buddy also knows this, so asking to see
your inbox gets you a way in rather than a location.

**What you could see**

- **Opening any file put its bookkeeping above its contents.** Files in Buddy's
  memory start with a metadata block, and in markdown a line of dashes under
  text means "make the line above a heading". So `summary:` and `access_count:`
  rendered as the largest thing on the page, above the text they described. The
  viewer now begins at the content, and shows the file's one-line summary under
  its name in the header, where it reads as a subtitle.

- **A file Buddy named was a path, not a door.** Any file it mentions inside
  your buddy directory is now a link. Files in its own memory show their name
  alone, because where Buddy files its notes is Buddy's business; files in your
  space keep their full path, because that is what lets you find them in a file
  manager or in an editor like Obsidian. Either way the full path is in the
  tooltip and in the panel header, so nothing is hidden — only moved out of the
  middle of a sentence.

- **Formatting inside a link showed its markup.** A link labelled in bold or in
  code displayed its asterisks and backticks instead of rendering. This had been
  true since links were added, and it was the reason paths arrived on screen
  wrapped in backticks.

**What was one small change away from going wrong**

- **The repo and the shipped binary could describe different prompts.** Buddy's
  core prompts are snapshotted into a file the packaged app reads, since the
  repo does not exist inside it. That snapshot is rebuilt during every release,
  so no release ever carried stale text — but nothing rebuilt it during ordinary
  work and nothing compared it, so an edited prompt could sit in the repository
  for weeks with the committed snapshot still quoting the previous wording. It
  is now checked on every test run.

**What changed underneath**

The status column in the requirements document is no longer maintained by hand:
a test cross-references every requirement against the scenarios and tests that
cite it, and fails in both directions — a requirement marked done that nothing
covers, and a requirement covered that nobody marked. Seven rows were wrong when
it was introduced, all of them work finished months ago and never ticked off.
`PROGRESS.md` went from fourteen hundred lines of accumulated sprint history to
a short list of what is actually open; the history it held is in git and in
these notes. Frontmatter parsing moved out of the worker so the interface could
reuse it rather than grow a second copy.

768 unit tests and 245 scenarios. Nothing about how Buddy remembers, decides or
schedules has changed — this release is entirely about what reaches your screen.
