## Buddy learns more from every conversation

Session reflects now capture the reasoning behind decisions, concrete facts, and
richer system observations — not just topic labels and thin conclusions. The
agent can also write to its own log during the session (not only at the end), and
volatile context like shifted dates or completed tasks is patched into memory
immediately instead of waiting for the next maintenance cycle.

**What you could see**

- **Richer session logs after closing Buddy.** The reflect that runs when you
  close a session now asks for the *why* behind decisions, preserves names,
  dates, and reference numbers, and invests more effort in spotting patterns
  worth remembering. If you re-read yesterday's log, the difference should be
  obvious.

- **The agent may write to the log during a conversation.** When a significant
  decision or lesson comes up, the agent can capture it immediately rather than
  relying on the reflect to reconstruct it after the fact. The session-end
  reflect still runs and will not duplicate what was already written.

- **"Right now" stays fresh between maintenance cycles.** If a conversation
  shifted a date, completed a task, or introduced a new constraint, the reflect
  patches the active context so the next session starts with accurate state.
  Previously this only happened during periodic consolidation, which could leave
  stale facts in place for days.

**What changed underneath**

The reflect prompt (`process-conversation.md`) gained a new step for detecting
active context changes and richer guidance for observations — exclusion criteria,
two-path rule candidates, and a concrete-facts quality rule. The output-only
suffix was rewritten to frame observations as the most valuable part of the
reflect instead of encouraging brevity. A new extraction and patching pipeline
(`extractRightNowPatches` / `applyRightNowPatches`) mirrors the existing
observations pipeline: the model judges, the worker writes.
