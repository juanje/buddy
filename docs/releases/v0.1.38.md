## Project linking for tasks

Tasks can now carry an optional `#project-slug` tag that links them to a project file in `user/projects/`. The assistant classifies captures with GTD vocabulary and the weekly consolidation checks that active projects still have pending actions.

**What you could see**

- **Tasks linked to projects.** When you capture work that belongs to a project, the assistant can tag it `#ley-dep` (or whatever slug matches your project file). The tag appears on the task line in `user/tasks.md`.
- **Add and list by project.** `tasks(action='add', params={..., project: 'slug'})` writes the tag; `tasks(action='list', params={project: 'slug'})` shows only that project's open items.
- **Clearer capture classification.** The assistant distinguishes a GTD *next action* (one concrete step) from a GTD *project* (outcome needing 2+ steps). Multi-step outcomes get a project file plus a first next action tagged to the project.
- **Project health in weekly review.** During consolidation, the assistant flags active projects in `user/projects/` that have no open tasks with their `#project` tag — a prompt to close, pause, or add a next step.
- **Task deletion prompt is now clear.** When the assistant wants to remove a task, the confirmation says "delete a task" instead of the misleading "access a file outside its folder".

**What changed underneath**

`TaskItem.project` parsed and serialized in `task-file.ts`; `add` and `list` actions extended in `task-actions.ts`. `agents-base.md` capture table and routing use GTD anchors; `consolidation.md` step 4 adds a project health check. Permission kind `"task-remove"` with dedicated i18n strings replaces the generic `"outside"` kind for `tasks:remove`. Five new BDD scenarios (@FR-TASKM-01..05); nine new unit tests.

1263 unit tests, 458 BDD scenarios. Nothing else should look or behave differently.
