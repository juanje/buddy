## Task lifecycle polish

Three improvements to how Buddy handles tasks after a real testing session exposed gaps in the lifecycle: completing a next action left the area hanging, outcome-shaped items slipped through as flat tasks, and related tasks were never proposed as projects.

**What you could see**

- **Completing or removing a next action left the area without guidance.** Buddy said "the next action for work is now free" and stopped — you had to ask which tasks remained and pick one yourself. Now the response includes how many open tasks are left in the area and suggests choosing a new next action before the area stalls.
- **Outcome-shaped tasks were captured without challenge.** Saying "update the work laptop" was accepted as a single task when it is really a project with several steps. Now Buddy recognises outcome-shaped language — "Update X", "Organise Y", "Prepare Z", "Sort out…" — and asks for the concrete first step before adding, or proposes one and creates a project file. If you insist it is one task, it captures it as-is.

**What changed underneath**

Weekly consolidation now reviews areas with three or more untagged open tasks and evaluates whether they share a completable outcome or have dependencies between them. When they do, it proposes a project to you via the deferred queue. When they don't — same area is not a shared outcome — it leaves them alone. The guard against catch-all or miscellaneous projects is explicit: a project needs a defined "done".
