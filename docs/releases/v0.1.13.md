## Linux shows up properly

The icon was missing on Fedora and other Linux desktops because the package
only installed a 1024×1024 PNG — a size most launchers never look for. Buddy
now ships icons at standard XDG sizes (32, 64, 128, 256, 1024) so GNOME,
KDE and others find and display it. The `.desktop` file also gains a
`Categories=Utility;` entry, which means Buddy appears in the expected
section of the application menu rather than floating uncategorised.

**What you could see**

- **No app icon on Linux (Fedora, GNOME, KDE).** The package only installed
  a single 1024×1024 icon. Desktop environments typically look for 48–256px
  variants; without them, they showed a generic placeholder. Buddy now
  installs five sizes, and the one most launchers prefer (256×256) was
  missing entirely — it has been added.

- **The app didn't appear in any category in the Linux application menu.**
  `Categories=` was empty in the `.desktop` file. It is now `Utility`.

**What changed underneath**

The RPM and `.deb` no longer pull in Perl and dozens of transitive
dependencies just for git — they depend on `git-core` instead, which is the
actual binary Buddy calls. Unused Windows icon assets (from the original
Tauri scaffold) were removed, and the README was rewritten for end users.

804 unit tests and 258 scenarios. If you are on macOS, nothing here changes
your experience — this release is entirely about how Buddy presents itself on
Linux.
